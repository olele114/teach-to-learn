# 课程质量约定

## 每课最小结构

1. 一个与长期目标相关的本课结果，以及可观察的完成标准。
2. 必要先修检查、首次出现术语的定义和一个具体用途。
3. 一段短讲解和一个已讲解例子，标注来源、简化假设及适用版本。
4. 一个不同于讲解例子的开放任务，附清楚的提交方式。
5. 收到真实回答后再给反馈、分级提示和必要答案。
6. 一条速查摘要、一个推荐原始来源，以及下一步或退出选择。

## 判断与反馈

- 评价用户实际提交的内容；区分知识错误、表达不清和任务本身有歧义。
- 默认用开放回忆或实际演示，避免选择题的位置、字数和措辞泄露答案。
- 已看过答案或依赖提示的成功只记为练习，不升级为独立完成。
- 引导用户解释原因或在新情境应用，不能只让其复述刚刚展示的句子。
- 不凭用户的礼貌回应、阅读时长、点击事件或文件生成推断学习结果。

## 可选 HTML

只有用户需要且宿主能写文件时才生成 HTML；纯文本课程始终可用。
页面使用语义化标题、明确的表单标签、键盘可用的控件、可见焦点和不依赖颜色的反馈。
默认不加载远程脚本、字体或分析服务；无 JavaScript 时也要能阅读并提交文字答案。
交互得分不是可靠身份验证或聊天回传机制；注明用户应如何把结果带回会话。
答案不在开放任务前直接展示；查看解析后须换新任务才能支持独立完成的判断。
多课共享样式或组件时放在学习目录 assets/，用相对路径，不引用 skill 安装目录。
除非已实际验证，不能宣称页面可访问性、代码执行或浏览器反馈通道已通过测试。
